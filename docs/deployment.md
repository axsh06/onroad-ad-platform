# Публикация ONROAD без своего домена

## Что уже подготовлено

- Next.js работает как полноценное серверное приложение; статический хостинг/GitHub Pages не подходит для кабинетов и API.
- `vercel.json` и `render.yaml` задают сборку. Docker для этих двух вариантов не требуется.
- `npm run deploy:build` проверяет настройки, генерирует Prisma Client, применяет миграции и собирает приложение. Никаких `db push`, сбросов или тестовых аккаунтов на production.
- PostgreSQL хранит пользователей, машины, заявки и метаданные фотографий.
- Закрытый Vercel Blob или S3-совместимый bucket хранит фотографии. Доступ идёт через `/api/media/:id`: до модерации только владелец/администратор, после одобрения — посетители каталога. Публичный доступ к самому bucket не нужен.
- Исходные JPG/PNG/WebP до 8 МБ сжимаются в браузере перед отправкой. Сервер принимает до 3 МБ, проверяет декодирование, уменьшает до 1600 px и удаляет EXIF, включая GPS. Это укладывается в лимит тела запроса Vercel 4,5 МБ.
- В разработке фотографии сохраняются в `.data`, а не в `public`. На production запись в локальную файловую систему запрещена.
- `/api/health` возвращает 200, когда мигрированная база доступна; иначе 503. Это проверка базы, не проверка доступа к хранилищу фотографий.

## Аккаунты и размещение данных

Нужны аккаунт хостинга, PostgreSQL и закрытое хранилище фотографий. Они принадлежат владельцу проекта. Секреты вводятся в Environment Variables хостинга, никогда в чат или GitHub.

Для демонстрации можно выбрать облачные сервисы с бесплатными тарифами и использовать вымышленные данные. Бесплатный Render засыпает; бесплатный Vercel Hobby предназначен для некоммерческого личного использования. Перед настоящим сбором персональных данных пользователей Казахстана нужно согласовать размещение базы, фотографий и резервных копий с требованиями РК. Настройки S3/PostgreSQL позволяют использовать и провайдеров в Казахстане.

## Обязательные настройки

| Переменная | Значение |
| --- | --- |
| `DATABASE_URL` | Строка подключения PostgreSQL. Для Vercel предпочтительно подключение через pooler провайдера. SSL по требованиям провайдера. |
| `DIRECT_URL` | Необязательно: прямое подключение для миграций, если pooler их не поддерживает. Используется только процессом миграций; также поддерживается автоматически созданная Neon переменная `DATABASE_URL_UNPOOLED`. |
| `NEXTAUTH_URL` | Точный HTTPS-адрес проекта, например `https://PROJECT.vercel.app` или `https://PROJECT.onrender.com`. |
| `NEXTAUTH_SECRET` | Случайная строка минимум 32 символа; локально можно создать `openssl rand -base64 32`. |
| `STORAGE_DRIVER` | `vercel-blob` для Vercel Blob или `s3` для S3. |
| `BLOB_STORE_ID` / `BLOB_READ_WRITE_TOKEN` | Для Blob подключить закрытое хранилище через Storage → Connect Project. Интеграция добавит доступ автоматически; не использовать NEXT_PUBLIC-префикс. |
| `S3_ENDPOINT` | HTTPS endpoint S3-совместимого сервиса; для обычного AWS S3 можно не задавать. |
| `S3_REGION` | Регион, указанный провайдером. |
| `S3_BUCKET` | Имя отдельного закрытого bucket для ONROAD. |
| `S3_ACCESS_KEY_ID` / `S3_SECRET_ACCESS_KEY` | Ключ с правами GetObject, PutObject и DeleteObject только на `car-photos/*` этого bucket. |
| `S3_FORCE_PATH_STYLE` | `true` для совместимых сервисов, требующих path-style; для AWS обычно `false`. |

Браузер общается только с ONROAD: CORS bucket для прямых загрузок не нужен. Не выдавайте ключу административный доступ к аккаунту. Включите резервные копии PostgreSQL и версионирование/резервирование файлов. Незавершённые загрузки остаются приватными; автоматическое удаление старых незавершённых загрузок пока не настроено.

## Вариант A — Vercel

1. В своём аккаунте импортировать `axsh06/onroad-ad-platform`, ветка `main`, Framework Next.js, корень репозитория.
2. Выбрать Node.js 22.x. Команда сборки берётся из `vercel.json`.
3. Подключить отдельную **пустую** PostgreSQL-базу и закрытое Vercel Blob-хранилище (`STORAGE_DRIVER=vercel-blob`). Заполнить настройки выше для Production. Локальная база автоматически не переносится.
4. Указать постоянный адрес проекта в `NEXTAUTH_URL`. Если адрес уточнился после создания проекта, изменить переменную и выполнить Redeploy.
5. Выполнить Deploy. Миграции создадут таблицы.
6. Не использовать production-базу для Preview. Для Preview нужны отдельные база, bucket, секрет и URL; только после их настройки добавить `PREVIEW_DATABASE_ISOLATED=true`. До этого preview-сборка намеренно завершается ошибкой.

## Вариант B — Render

1. Создать Blueprint из того же репозитория либо Web Service вручную с настройками из `render.yaml`.
2. Blueprint создаёт только приложение на бесплатном тарифе. База и S3 подключаются отдельно. Платные ресурсы автоматически не заказываются.
3. Указать настройки выше, включая точный адрес `onrender.com`.
4. Build: `npm ci && npm run deploy:build`. Start: `npm start -- --hostname 0.0.0.0`. Health check: `/api/health`.
5. Для постоянного бизнес-сервиса выбрать подходящий платный тариф; бесплатный сервер может засыпать. Не использовать временную бесплатную базу как единственное хранилище реальных данных.

## Администратор

Зарегистрировать свой аккаунт на развёрнутом сайте. Из доверенной среды с подключением к **нужной** базе выполнить:

```sh
npm run admin:promote -- owner@example.com
```

Команда меняет роль только существующего пользователя. Выйти и войти заново для обновления JWT. Не публиковать публичный API назначения администратора и не хранить пароль в исходниках.

## Уже существующая база

Для новой пустой облачной базы достаточно `prisma migrate deploy`. Если база раньше создавалась через `db push`, нельзя применять начальную миграцию поверх существующих таблиц. Сначала сделать резервную копию, сравнить структуру с начальной миграцией и только при совпадении зарегистрировать baseline:

```sh
npx prisma migrate resolve --applied 20261013000000_initial
npx prisma migrate deploy
```

Это уже выполнено для локальной `onroad_dev`: структура совпадала, затем добавлена таблица фотографий. Старые локальные файлы из `public/uploads` автоматически не переносятся. Перед переносом существующих объявлений нужен отдельный импорт файлов и обновление их URL.

## Приёмка после фактического развёртывания

- `/api/health` отвечает 200.
- Регистрация и вход обеих ролей работают по HTTPS.
- Фотографии сохраняются, видны владельцу/администратору, до одобрения закрыты от анонимного пользователя.
- Одобренная машина появляется в каталоге, фото открываются в конфигураторе.
- Запрос компании виден в кабинетах и у администратора.
- После нового деплоя записи и фотографии остаются доступны.
- Калькулятор рассчитывает и скачивает файл.
- Проверены восстановление резервной копии, ограничения хостинга и права доступа.

Облачная проверка 13 октября 2026: health 200, регистрация и вход SELLER/BUYER, отказ в недопустимых правах, проверка формата изображений, приватное фото до модерации, публичное после одобрения, создание и подтверждение заявки — пройдены. Калькулятор пересчитывает 5 авто × 3 зоны × 3 месяца × 150 000 ₸ = 6 750 000 ₸. Получение скачанного TXT автоматикой браузера пока не подтверждено. Проверка восстановления резервной копии не выполнялась. 13 октября 2026 создана база Neon Free `onroad-db` и закрытое Vercel Blob-хранилище `onroad-photos` в регионе IAD1. Оба сервиса подключены только к Production проекта `onroad-ad-platform`. Blob использует автоматически обновляемые OIDC-учётные данные. Сайт доступен по https://onroad-ad-platform.vercel.app. По решению владельца это личный прототип для тестирования на Hobby. Реальные платежи и восстановление пароля по почте пока не подключены; юридические тексты остаются черновиками.

## Обновления и обслуживание

Изменения в ветке `main` репозитория GitHub автоматически запускают новый deployment. Перед публикацией выполняются миграции и проверка конфигурации; данные лежат отдельно от файлов приложения. Preview не использует рабочие секреты и пока намеренно не запускается без отдельной базы. Для отката кода используйте Vercel Deployments; откат кода не отменяет миграции базы.

Облачная база изначально пустая: локальные автомобили и аккаунты автоматически не переносятся. Для входа администратору после назначения роли требуется выйти и войти заново.
