# ONROAD

Пилот платформы, которая соединяет владельцев автомобилей и компании для размещения рекламы на машинах. В проекте сохранены исходная двуязычная главная ONROAD и калькулятор кампании (`/campaign.html`), а функции второго проекта добавлены как отдельные страницы приложения.

## Что уже есть

- главная и калькулятор бюджета ONROAD;
- каталог одобренных автомобилей с фильтрами, карточкой машины и выбором рекламной зоны;
- регистрация компании и владельца машины, вход и сессии;
- подача автомобиля на модерацию с фотографиями;
- заявки компаний на бронирование места и выбор эскиза макета;
- кабинет владельца, рекламодателя и администратора;
- ручная модерация машин и подтверждение заявок;
- страницы «О платформе», политика данных и условия сервиса (юридические тексты пока черновые).

В каталоге и калькуляторе могут быть демонстрационные изображения и цены. Пользовательская заявка сохраняется в базе, если настроена PostgreSQL. Онлайн-оплата не подключена: интерфейс и API не создают поддельные платежи, QR-коды или подтверждения. Суммы выплат и доля платформы требуют отдельного согласования и не являются офертой.

## Локальный запуск

Нужны Node.js 20.9+ и PostgreSQL. В каталоге проекта:

```bash
npm install
cp .env.example .env
```

Заполните в `.env` `DATABASE_URL`, `NEXTAUTH_URL` и `NEXTAUTH_SECRET`. Создайте секрет, например командой `openssl rand -base64 32`, и укажите локальный URL `http://localhost:8765`. Файл `.env` используется и приложением, и Prisma CLI.

Затем примените схему и запустите сайт:

```bash
npx prisma generate
npx prisma db push
npm run dev -- --port 8765
```

Откройте `http://localhost:8765/`. Калькулятор находится по адресу `http://localhost:8765/campaign.html`.

Для базы данных пока нет готовых тестовых аккаунтов: зарегистрируйте пользователя через сайт. Чтобы проверить модерацию, роль администратора следует назначить вручную в PostgreSQL после регистрации, пока не добавлена безопасная административная процедура.

## Перед публичным запуском

1. Подключить и проверить PostgreSQL, секреты, домен и HTTPS.
2. Подключить закрытое S3-совместимое хранилище фотографий. Код поддерживает S3; ключи и bucket ещё нужно настроить. Документы через загрузчик не принимаются. В разработке используется `.data`.
3. Подготовить окончательные политику данных, условия, согласия и реквизиты оператора с юристом в Казахстане.
4. Подключить настоящий платёжный провайдер и проверку подписанных webhook, затем отдельно настроить расчёты и выплаты.
5. Удалить демонстрационные изображения/цены или заменить их на реальные карточки с подтверждёнными данными.
6. Добавить контролируемое создание администратора, ограничения доступа, резервные копии базы и мониторинг ошибок.

Сейчас приложение является пилотным прототипом и не настроено для приёма реальных платежей или публичного сбора чувствительных документов.

## Деплой без собственного домена

См. [пошаговую инструкцию для Vercel и Render](docs/deployment.md). Подготовлены миграции, настройки хостинга и постоянное хранение фотографий. Облачные сервисы пока не подключены.
